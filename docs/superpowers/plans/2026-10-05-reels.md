# Reels (Knitted Doll) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the n8n "Reel · Heart-Tug (Knitted Doll)" workflow a Reels feature of Unique Names Posting: Gemini writes a reviewable script in the web app; the owner's PC makes voice (Chatterbox in ComfyUI), word timings (faster-whisper), images (ComfyUI Z-Image) and the video (ffmpeg) for free.

**Architecture:** Same pull model as name cards. The web app (Next.js server actions) writes the script with Gemini and stores `reels` + `reel_scenes` rows in Supabase; on approval the reel is queued. The PC worker claims reel steps (voice → timing → images → render) through a SQL function, resumes after interruptions, saves the full MP4 to the OneDrive Pictures folder and uploads a 720p preview to a private bucket. Realtime drives live progress.

**Tech Stack:** Next.js 16 / React 19 / Tailwind 4 / shadcn (existing kit), Supabase (Postgres, RLS, realtime, storage), Gemini REST (`lib/ai/gemini.ts generateJson`), Python 3.12 worker (stdlib + Pillow), ComfyUI Desktop API, Chatterbox (ComfyUI custom node), faster-whisper, imageio-ffmpeg; vitest + PGlite + jsdom; python unittest.

**Spec:** `docs/superpowers/specs/2026-10-05-reels-design.md`. n8n prompt source: `docs/reference/reel-knitted-doll-n8n.md`.

## Global Constraints

- Script model `gemini-3.1-pro-preview` via the existing server-only `generateJson` (header key, never in a URL, never logged). Topic optional; blank = Gemini picks a fresh early-years (0–5) topic; never repeat a title already in `reels`.
- One image per short narration line (6–10 words), about 25–40 scenes; `settings.reel_max_images` default 40, range 10–40.
- Image prompts: positive-only wording (cfg 1, no negative prompt) — no "avoid / no X / NOT a …" phrases except the existing `NO_TEXT` line; never the word "camera"; the script's two-doll cast is injected into every scene prompt.
- Images: Z-Image Turbo graph (`worker/render.py comfy_graph`) at 1088×1920, fitted to 1080×1920.
- Voice: Chatterbox (MIT) via ComfyUI; default voice until `settings.reel_voice_path` is set.
- Video: 1080×1920 H.264 + AAC, Ken Burns zoom per scene, word-by-word yellow captions; full MP4 → `C:\Users\rober\OneDrive\Pictures\Unique Names\Reels\<YYYY-MM-DD> <title>.mp4`; 720p preview ≤ 15 MB target (hard cap 45 MB) → private bucket `reels`; previews older than 14 days deleted.
- Approve / redo / re-render obey the generate lock (`canGenerate` client + `generateLockReason` server).
- Cards and reels never use the GPU at the same time: reel steps are claimed only when no card is `queued`/`generating`/`restamp`.
- Every new server action: `requireOwner()` first, UUID validation, version-guarded updates.
- Live DB / live worker safety: the owner runs `supabase/migrations/005_reels.sql`; the live worker runs from this checkout — never stop or restart it (the owner restarts it). Real data is read-only in browser checks.
- Existing conventions: Write/Edit tools (Read before editing), mobile-first 44px targets, light + dark tokens, shadcn kit (after any `npx shadcn add`, re-apply the accent/muted class rewrites; `tests/shadcn-tokens.test.ts` guards it). ### Task 4: Server actions for reels

**Files:**
- Create: `lib/actions/reels.ts`, `tests/reel-actions.test.ts`

**Interfaces:**
- Consumes: `writeReelScript`, `scenePrompt`, `generateLockReason`, `requireOwner`, `fail`, `UUID_RE`, fake Supabase test helper.
- Produces (all return `ActionResult<…>`):
  - `writeReelScriptAction({ topic?: string }): { reelId }` — topic ≤ 120 chars; loads all reel titles + `reel_max_images`; calls `writeReelScript`; if the title matches an existing one (case/space-insensitive) retries up to 2 times; inserts `reels` (status `script`, `doll_cast = script.cast`) + `reel_scenes` (status `pending`, `image_prompt = scenePrompt(cast, idea, beat)`, random seed) ; revalidates `/reels`.
  - `rewriteReelScriptAction(reelId)` — only in `script`; replaces title/`doll_cast`/scenes (delete + insert scenes) using the stored topic.
  - `saveReelScriptAction(reelId, { title, lines: { id, narration, idea }[] })` — only in `script`; validates; rebuilds `image_prompt` for changed ideas.
  - `approveReelAction(reelId)` — lock check; only from `script`; sets reel `queued`, all scenes `queued`.
  - `redoReelSceneAction(sceneId)` — lock check; scene `done|failed` → `queued` (new seed, attempts 0), reel → `queued`, clears `preview_path`/`pc_path`.
  - `skipReelSceneAction(sceneId)` — only when the reel is `needs_attention`; scene → `skipped`, reel → `queued`.
  - `rerenderReelAction(reelId)` — lock check; reel `ready|failed` with all scenes `done|skipped` → `queued`, clears `preview_path`.
  - `deleteReelAction(reelId)` — removes storage objects under `reels/<id>/` best effort, deletes the row (scenes cascade).
